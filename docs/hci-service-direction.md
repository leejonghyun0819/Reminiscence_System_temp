# Reminiscence Note 서비스 방향과 1차 구현 기준

이 문서는 사용자 분석, 과업 분석, 맥락 분석 수업 자료와 2026-09-30 피드백을 현재 프로젝트에 적용하기 위한 설계 기준이다. 아래 사용자 유형은 아직 인터뷰나 관찰로 검증되지 않은 **가설**이다.

## 서비스 정의

> 사진과 사용자의 단서를 바탕으로 AI가 사진별 인터뷰를 진행하고, 확인된 기억을 서사형 추억 노트로 복원하는 서비스

단순 앨범과의 차이는 사진을 모아 보여주는 데 있지 않다. 사진만으로는 알 수 없는 사람, 사건, 감각, 전후 상황을 질문하고, 사용자가 확인한 사실을 기록으로 남기는 데 있다.

## 사용자 가설

| 구분 | 사용자 가설 | 핵심 목표 | 예상 어려움 |
|---|---|---|---|
| 주 사용자 | 자신의 과거 사진은 갖고 있지만 정리하거나 글로 쓰기 어려운 사람 | 사진을 보며 기억을 되찾고 개인 기록을 완성한다 | 어디서부터 말해야 할지 모르고 긴 글쓰기를 부담스러워한다 |
| 보조 사용자 | 부모·조부모 등 가족의 오래된 사진을 디지털로 정리하는 사람 | 사진 주인의 기억을 인터뷰해 가족 기록으로 보존한다 | 본인이 겪지 않은 장면을 AI가 사실처럼 단정할 위험이 있다 |

이 가설은 이후 사용자 인터뷰에서 사진 보관 습관, 기록 동기, 인터뷰 상대, 개인정보 우려, 입력 방식 선호를 확인해 수정해야 한다.

## 핵심 과업 시나리오

| 요소 | 기본 시나리오 |
|---|---|
| Trigger | 정리하지 못한 과거 사진을 발견하거나 가족의 기억을 남기고 싶어진다 |
| Intent | 사진의 맥락을 되살려 읽을 수 있는 추억 기록으로 만들고 싶다 |
| Steps | 사진 선택 → 알고 있는 맥락 입력 → AI의 사진별 질문 확인 → 사진을 보며 답변 → 생성된 노트 검토·보관 |
| Breakdown | 사진만으로 AI가 관계·장소를 잘못 추정함, 질문이 너무 포괄적임, 사용자가 기억하지 못함, 사진 주인과 입력자가 다름 |
| Strategy | 사용자 단서를 사진 추정보다 우선함, 질문마다 근거 사진을 연결함, 모르는 답변을 허용함, 입력자와 기억 주인을 구분함 |

### 극단·실패 시나리오

- 사진의 시기와 장소를 전혀 모르면 비워 둔 채 시작하고, AI는 보이는 단서 범위에서만 질문한다.
- 가족 사진을 대신 정리하면 1인칭 경험으로 단정하지 않고 “사진 주인에게 확인할 내용”을 질문한다.
- 사용자 설명과 사진 추정이 충돌하면 사진 추정으로 덮어쓰지 않고 확인 질문을 만든다.
- 답변이 대부분 “기억 안 남”이면 빈 내용을 소설처럼 채우지 않고 확인된 장면과 미확인 부분을 구분한다.

## 맥락 모델

| 단계 | 수집 정보 | 역할 |
|---|---|---|
| 자동 수집 | 사진 순서, 시각적 사실, 반복 인물·물건·공간, 가능하면 EXIF | 질문의 시각적 근거 |
| 초기 사용자 맥락 | 기억 주인, 기록 목적, 대략적인 시기·장소·사람, 사진을 고른 이유 | AI 분석의 방향과 관점 설정 |
| 동적 인터뷰 | 사진별 관계·사건·감각·전후 상황, 여러 사진 사이 변화 | 사진 밖의 개인 기억 확인 |
| 사용 맥락 | 혼자/가족과 사용, 기기, 입력 부담, 개인정보 환경 | 이후 UX 검증 항목 |

## 현재 구현에 적용하는 요구사항

1. 신규 등록 화면에서 사진과 함께 최소 맥락을 선택적으로 입력한다.
2. 질문 생성 프롬프트는 사용자가 제공한 맥락을 사진 추정보다 우선한다.
3. 이미 입력된 사실을 그대로 되묻지 않고, 특정 사진의 단서와 연결해 더 깊은 사건을 묻는다.
4. 모든 질문은 연결 사진 번호를 가지며 사용자가 질문 화면에서 해당 사진을 확인할 수 있어야 한다.
5. 큐레이션은 이후 인터뷰 답변, 초기 사용자 맥락, 사진의 직접 관찰, 추정 순으로 신뢰한다.
6. `memoryContext`를 `interviewData`와 함께 저장해 기존 앨범 재분석 때 다시 사용한다.
7. 맥락이 없는 기존 앨범도 기존 방식으로 재분석할 수 있어야 한다.

## 기능 영향과 의도한 절충

| 변경 | 기대 효과 | 비용·위험 | 대응 |
|---|---|---|---|
| 초기 맥락 입력 | AI가 엉뚱한 방향으로 질문할 가능성 감소 | 사진 등록 전 입력 부담 증가 | 모두 선택 입력으로 두고 짧은 칩과 예시를 제공 |
| 기억 주인 구분 | 가족 사진을 사용자 경험으로 오인하는 문제 감소 | 선택지가 사용자 상황을 완전히 표현하지 못할 수 있음 | “잘 모름”과 자유 설명 제공 |
| 기록 목적 수집 | 질문과 최종 글의 관점 개선 | 목적별 문체 최적화는 추가 구현 필요 | 우선 프롬프트 맥락으로 전달하고 후속 검증 |
| 맥락 저장 | 재분석의 일관성 향상 | 개인 정보가 앨범 메타데이터에 남음 | 실제 사용자 조사에서 고지·삭제·보호 요구 검증 |

## 검증할 성공 기준

- 사용자는 AI가 왜 해당 질문을 했는지 연결 사진과 단서로 이해할 수 있는가?
- 이미 제공한 시기·장소·사람을 반복해서 묻는 질문이 줄어드는가?
- 사진 주인이 다른 경우에도 잘못된 1인칭 서술이 생성되지 않는가?
- 완성된 노트에 사진만 보고 만든 일반적 표현보다 사용자 고유의 사건이 포함되는가?
- 맥락 입력 부담 때문에 사진 등록을 포기하지 않는가?

정량 지표는 사용자 테스트 전에 임의로 확정하지 않는다. 먼저 5~8명의 탐색 인터뷰와 과업 관찰로 질문 이해도, 입력 부담, 잘못된 추정 사례를 수집한 뒤 기준을 정한다.
